## Scheduling Algorithm Descriptions

### **1. Lane Rotation (Perfect N-Stage)**

This is the gold standard for "equalizer" racing because it eliminates track bias (the "fast lane" advantage).

* **How it works:** Each racer runs exactly N times, where N is the number of lanes on your track. They rotate through every single lane once.
* **The Logic:** If you have 4 lanes, a scout will race 4 times—once in Lane 1, once in Lane 2, and so on.
* **Pros:** Perfectly fair; very easy to explain to parents.
* **Cons:** You might end up racing the same 3 people in every heat, which can be repetitive.

### **2. Partial Perfect Chart (PPC)**

If you want variety in opponents *and* lane fairness, PPC is the industry favorite. It uses combinatorial design to ensure that not only does everyone race in every lane, but they also face as many different opponents as possible.

* **How it works:** It uses a "Steiner Triple System" or similar balanced incomplete block design (BIBD).
* **The Logic:** The algorithm selects matchups so that the number of times Scout A faces Scout B is nearly identical across the whole roster.
* **Pros:** High "Social Variety"—kids get to race against a wider variety of friends.
* **Cons:** Mathematically complex to generate from scratch (though libraries exist to handle this).

### **3. Dynamic Speed-Based (Stearns Method)**

This is often used for "Finals" or "Pro" leagues. It attempts to group racers of similar speeds together as the day progresses.

* **How it works:** After an initial round of Lane Rotation, the system calculates average speeds. The next round of heats is generated by pairing the fastest cars against each other and the slower cars against each other.
* **Pros:** Creates "photo finish" excitement in every heat because the cars are evenly matched.
* **Cons:** Can feel discouraging for the slower group if they realize they are in the "slow heats."

### **Summary Table: Which algorithm to choose for a race?**

| Algorithm | Primary Goal | Complexity | Best For... |
| --- | --- | --- | --- |
| **Lane Rotation** | Physical Fairness | Low | Smaller Packs / Tigers |
| **PPC** | Opponent Variety | High | Large Packs (50+ scouts) |
| **Speed-Based** | Excitement/Drama | Medium | Grand Finals / District |

## Scheduling Algorithm Implementation Details

Below is a technical specification for the three primary Pinewood Derby scheduling methods.

# Technical Specification: Race Scheduling Algorithms

## 1. Perfect N-Stage Rotation

**Goal:** Absolute Lane Neutrality.
**Context:** Best for Den-level racing where fairness is the only priority.

### Algorithm Logic

Given a list of `P` Participants and `L` Lanes, the system generates exactly `P` heats. For any Heat `i`, the Participant assigned to Lane `j` is the one at index `(i + j) % P`.

### ASCII Representation (4 Participants, 3 Lanes)

```text
Participants: [A, B, C, D]
Lanes: 3

Heat 0: | Lane 1: A | Lane 2: B | Lane 3: C |  (Indices: 0, 1, 2)
Heat 1: | Lane 1: B | Lane 2: C | Lane 3: D |  (Indices: 1, 2, 3)
Heat 2: | Lane 1: C | Lane 2: D | Lane 3: A |  (Indices: 2, 3, 0)
Heat 3: | Lane 1: D | Lane 2: A | Lane 3: B |  (Indices: 3, 0, 1)

```

### Implementation Constraints

* `L <= P` must be true.
* The `Participants` list should be shuffled **once** before the loop to randomize initial pairings.

## 2. Partial Perfect Chart (PPC)

**Goal:** Lane Neutrality + Maximized Opponent Variety.
**Context:** Best for large groups where you want Scouts to race against different friends.

### Algorithm Logic

This is a Balanced Incomplete Block Design (BIBD). It requires that:

1. Every Participant races in every Lane exactly once.
2. The number of times Participant X races Participant Y is minimized/balanced.

### Implementation Pattern (Greedy Optimization)

1. Generate a "Lane Matrix" where each row is a Heat and each column is a Lane.
2. Fill "Lane 1" with a randomized sequence of all Participants `[0...P-1]`.
3. For subsequent lanes, pick a Participant who:
* Has not yet occupied this specific Lane.
* Has the lowest cumulative "Matchup Score" with the Participants already assigned to the current Heat.



### ASCII Matchup Tracking

```text
Matchup Matrix (P x P):
    A B C D
A [ - 1 1 0 ] <- Track how many times A has raced others.
B [ 1 - 0 1 ]    Goal: Keep these numbers as close to 
C [ 1 0 - 1 ]    equal as possible across the roster.
D [ 0 1 1 - ]

```

## 3. Stearns Method (Dynamic Seeding)

**Goal:** Competitive Parity (Excitement).
**Context:** Best for Grand Finals or "Top 10" shootouts.

### Algorithm Logic

Heats are generated based on real-time performance data (Average Time or Points). This clusters "fast" cars together for more exciting finishes.

### Process Flow

1. **Sort:** Order Participants by average race time (Fastest to Slowest).
2. **Cluster:** Group the sorted list into blocks of size `L`.
3. **Rotate:** Assign lanes based on a "Lane Memory" to ensure no car repeats a lane from a previous stage.

### ASCII Heat Clustering (9 Racers, 3 Lanes)

```text
[Rank 1, 2, 3] -> Heat A (Fastest)
[Rank 4, 5, 6] -> Heat B (Middle)
[Rank 7, 8, 9] -> Heat C (Slowest)

Result: Photo finishes in Heat A; meaningful races in Heat C.

```

## Agent Implementation Cheat-Sheet

| Feature | N-Stage | PPC | Stearns |
