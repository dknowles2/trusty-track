# Task: Frontend Check-In Barcode/QR Scanning

## Goal

Add camera-based barcode/QR code scanning to the check-in flow, allowing operators to scan a racer's printed barcode to immediately pull up their check-in record.

## Background

SPEC.md describes the Race Check-In flow:

> "If 'Printables' were previously utilized, we want a race 'check-in' operator to be able to scan the barcode or QR-code to look up the participant. This should not require additional hardware — if using a laptop or physical computer, the attached USB camera should be able to convert a barcode into a participant record; if using a mobile phone or tablet, the onboard camera should be able to do the same."

The existing `CameraCapture.tsx` component handles photo capture but does not implement barcode decoding.

## Steps

1. **Add Barcode Scanning Dependency**
   - Add a browser-compatible barcode/QR scanning library to `package.json`.
   - Good options: `@zxing/browser` (ZXing for TypeScript), or `html5-qrcode`.
   - Prefer a library that supports both QR codes and standard barcodes.

2. **Create `BarcodeScanner.tsx` Component**
   - Build a new component that:
     - Activates the device camera (using `getUserMedia` like `CameraCapture.tsx`)
     - Continuously decodes frames looking for a barcode/QR code
     - Emits an `onScan(racerId: number)` callback when a code is detected
     - Shows a visual viewfinder/overlay to guide the operator
     - Includes a "Stop Scanning" button to dismiss the camera
   - The QR code encodes the racer ID (or a racer lookup URL). Parse out the ID on decode.

3. **Integrate into RaceDetails Check-In Flow**
   - In `RaceDetails.tsx`, add a "Scan to Check In" button (near the top of the roster or as a floating action button on mobile).
   - Clicking the button opens a modal containing `BarcodeScanner`.
   - On successful scan, close the scanner and open `CheckInModal` pre-populated with the scanned racer.

4. **Fallback for Non-Camera Devices**
   - Provide a text input field to manually type a car number or racer ID as a fallback.
   - Auto-focus the input and submit on Enter, jumping to the matching racer's check-in flow.

## Verification

- Test scanning a QR code generated by the backend barcode endpoint.
- Verify the correct `CheckInModal` opens for the scanned racer.
- Verify the manual entry fallback works correctly.
- Test on both desktop (USB webcam) and mobile (onboard camera).

## Dependencies

- Requires `01_backend_generation.md` to generate printable QR codes.
- Related to `02_frontend_print_ui.md` (the printed QR codes are scanned here).
